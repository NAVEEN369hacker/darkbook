# 08 — Mobile App (React Native, iOS + Android)

> **v2 identity model** — see [12-changelog.md](./12-changelog.md). The mobile app handles DID-key storage in Keychain/Keystore, daily background rotation, E2E DM decrypt in JS, and the rotation banner. The DID is never displayed.

The mobile app is the primary surface. It is a React Native app built with Expo, designed to feel native on both platforms while sharing 95%+ of the codebase with the web client.

## 5. Cryptography on mobile

```ts
// lib/crypto/index.ts
import * as Keychain from "expo-keychain";
import * as Crypto from "expo-crypto";

export async function generateIdentityKeyPair() {
  // ECDH P-256 then convert to ECDSA-capable (P-256 supports both)
  // The device secret is a 32-byte random token stored in SecureStore.
  // It's used for the HMAC proof at /auth/login and /auth/device/register.
  const deviceSecret = await Crypto.getRandomBytesAsync(32);
  await Keychain.setGenericPassword("ghostline.deviceSecret", base64(deviceSecret), {
    accessible: Keychain.ACCESSIBLE.AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY,
  });

  // The signing keypair is non-extractable and bound to the device.
  const { publicKey, privateKey } = await Crypto.subtle.generateKey(
    { name: "ECDSA", namedCurve: "P-256" },
    false,
    ["sign", "verify"]
  );
  const spki = await Crypto.subtle.exportKeyAsync("spki", publicKey);
  const pkcs8 = await Crypto.subtle.exportKeyAsync("pkcs8", privateKey);
  await Keychain.setGenericPassword("ghostline.deviceKey", base64(pkcs8), {
    accessible: Keychain.ACCESSIBLE.AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY,
  });

  // DM thread keys are stored in a separate, encrypted SQLite row,
  // keyed by threadId. Wrapped under the device key.
  await openDmKeyStore();

  return { publicKeySpki: pem(spki), keyId: "k1" };
}
```

For v1, the private key is stored in Keychain/Keystore as a non-extractable, passphrase-wrapped key. Biometric requirement is a v2 toggle.

## 6. Signed-request middleware (axios)

Same canonicalization as web (see [03 §4](./03-identity-and-crypto.md#4-authenticated-request-shape)) but using `expo-crypto`:

```ts
axios.interceptors.request.use(async (config) => {
  const { accessToken, keyId } = store.getState().auth;
  const ts = new Date().toISOString();
  const nonce = base64url(await Crypto.getRandomBytesAsync(16));
  const bodyStr = config.data ? JSON.stringify(config.data) : "";
  const bodyHash = await Crypto.digestStringAsync(
    Crypto.CryptoDigestAlgorithm.SHA256,
    bodyStr
  );
  const canonical = [
    config.method?.toUpperCase(),
    config.url,
    ts,
    nonce,
    bodyHash,
  ].join("\n");
  const sig = await signWithStoredKey(canonical); // Keychain access
  config.headers.set("Authorization", `Bearer ${accessToken}`);
  config.headers.set("X-Ghost-KeyId", keyId);
  config.headers.set("X-Ghost-Timestamp", ts);
  config.headers.set("X-Ghost-Nonce", nonce);
  config.headers.set("X-Ghost-Signature", sig);
  return config;
});
```

## 9. Realtime

* Open socket at app start (after auth).
* Reconnect with exponential backoff capped at 30s.
* On reconnect, re-subscribe to current room.
* On app background, drop the socket; on foreground, re-open and reconcile.

## 9b. Daily UID rotation (background + foreground)

The mobile app owns the rotation clock because iOS and Android can wake the app at specific times.

### iOS — `BGAppRefreshTask`

```ts
import * as BackgroundFetch from "expo-background-fetch";
import * as TaskManager from "expo-task-manager";

const ROTATION_TASK = "ghostline.uid.rotation";

TaskManager.defineTask(ROTATION_TASK, async () => {
  const { nextRotationAt, accessToken } = store.getState().auth;
  if (!accessToken) return BackgroundFetch.Result.NoData;
  const ms = +new Date(nextRotationAt) - Date.now();
  if (ms > 10 * 60_000) return BackgroundFetch.Result.NoData; // too early

  try {
    const r = await rotateSession({ currentAccessToken: accessToken });
    store.dispatch(authRotated(r));
    return BackgroundFetch.Result.NewData;
  } catch (e) {
    return BackgroundFetch.Result.Failed;
  }
});

await BackgroundFetch.registerTaskAsync(ROTATION_TASK, {
  minimumInterval: 15 * 60,         // 15 min
});
```

If the user is offline at midnight, iOS may not wake the app. When the user next opens the app, the server returns the *latest* UID via `POST /auth/login` (the existing login flow).

### Android — `WorkManager`

Same logic, scheduled with `OneTimeWorkRequest` triggered by `nextRotationAt`. Constraints: network connected.

### Foreground UX

The app shows a `<RotationBanner>` (see [07](./07-web-frontend.md#identitychip-uid-displayname-colorhex-uidissuedat-)) on every screen when `msUntilRotation < 4h`. At T-5min, a full-screen "you're about to become someone new" modal appears. At T-0, the rotation runs silently and a toast confirms the new handle.

### Local cleanup on rotation

The mobile app proactively purges its local state at T-0:

* IndexedDB / SQLite rows for today's posts, comments, votes, follows, drafts
* DM `K_thread` keys in the encrypted store
* MMKV cache
* Pending outbox entries for the old UID (they would 401 anyway)

The new UID's local state starts empty (just the credentials).

## 9c. DM decryption

```ts
// On opening a DM thread:
const wrappedKey = await getSelfWrappedKey(threadId);     // IndexedDB
const devicePriv = await loadDevicePrivateKey();          // Keychain
const K_thread = await unwrapKey(wrappedKey, devicePriv); // ECDH + AES-GCM decrypt

const messages = await api.getDmMessages(threadId);
const decrypted = await Promise.all(messages.items.map(async m => ({
  ...m,
  plaintext: await decryptMessage(K_thread, m.ciphertext, m.nonce)
})));
```

If `unwrapKey` fails (e.g., this is a new device install), the thread is unrecoverable. The UI shows: "This conversation can no longer be read on this device." The user can delete the thread.

The web can be screenshotted; the mobile app **must** discourage it because posts can contain confessions.

### iOS

* Listen to `UIApplication.userDidTakeScreenshotNotification` → show a modal: "Screenshots can be shared. Be careful what you post." with `OK`.
* For sensitive screens (composer, post detail if user toggled a "sensitive content" flag), set the screen as `protected` via adding an overlay view in the app switcher snapshot.

### Android

* On sensitive screens, set `WindowManager.LayoutParams.FLAG_SECURE`. The system screenshot API and screen record will return a black image.
* Listen to `MediaProjection` start (best-effort) and warn.

## 11. Offline behavior

* Drafts are saved to SQLite.
* On launch, the home feed shows "You're offline" and a cached last-good page from MMKV.
* Submits queue in `outbox` table; the app retries with exponential backoff and surfaces failures with a "Couldn't post" toast.
